# bastion v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use subagent-driven-development (recommended) or
> executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax. Read
> `AGENTS.md`/`node_modules/next/dist/docs/` before writing Next.js code: Next 16 differs from training data
> (`proxy.ts` not middleware, async `params`, `after` from `next/server`).

**Goal:** rebuild bastion as a sign-in-free workbench where all eight products are usable live and
chainable into a durable, publicly verifiable dossier.

**Architecture:** a pure capability table drives one gateway pipeline (rate limit → budget → contract-v2
token → call → parse → audit). Dossiers are a Postgres step machine advanced one stage per invocation.
UI is RSC pages plus small client islands, in the existing dark terminal style.

**Tech stack:** Next.js 16 App Router, React 19, TypeScript strict, Zod 4, Drizzle + postgres.js on Neon,
Upstash (ratelimit + counters), `jose` (Ed25519), Tailwind 4, Biome, Vitest, Playwright.

**Spec:** `docs/specs/21-bastion-v2.md` (design) and `docs/specs/22-platform-contract-v2.md` (tokens).

## Global constraints

- Branch `v2`; never push to `main` (the orchestrator merges after the backends' contract-v2 rollout).
- No sign-in anywhere. No cookies are set by bastion.
- Downstream hosts (defaults in code, overridable by env): paper-trail
  `https://paper-trail-backend-jjpf.onrender.com`, magpie `https://magpie-backend-t4bb.onrender.com`,
  inkprint `https://inkprint-backend.onrender.com`, inkthread `https://inkthread-backend.onrender.com`,
  slowquery `https://slowquery-demo-backend.onrender.com`, feathers-demo
  `https://feathers-demo-rznj.onrender.com`. Frontends: paper-trail `-sable`, magpie `-three`, inkprint,
  slowquery-dashboard, inkthread (`*.vercel.app`, exact names in `src/platform/registry/products.ts`).
  Never use a host on the never-use list (`paper-trail-backend.onrender.com`, `bastion.vercel.app`, …).
- Secrets: only those already on Vercel. Derive new keys with HKDF-SHA256 from `IRON_SESSION_PASSWORD`
  (info strings `bastion/visitor/v1`); `BASTION_SIGNING_KEY_PRIVATE`, `BASTION_KEY_ID` as today.
- Budget defaults (env-overridable, per UTC day): `debate` 4, `upload` 3, `leakscan` 10, `scrape` 30,
  `certify` 200, `feathers.write` 50. Per-visitor rate limit: 30 calls/min; dossier creation 3/hour.
- Upload limit through bastion: 4 MB (Vercel's function body limit is 4.5 MB).
- Health: 8 s probe ⇒ `asleep` on timeout; wake holds up to 90 s.
- Runner: one stage per invocation, 240 s stage budget, `maxDuration = 300`, lease 270 s, poll
  `not_before` +3 s, max 3 attempts per stage, ≤ 12 evidence items sealed.
- Every downstream response is parsed with Zod; no `as T` across the HTTP boundary.
- Coverage ≥ 80 % lines on `src/` with per-module floors for `src/platform/**`, `src/capabilities/**`,
  `src/dossier/**` at 90 %.
- Commits: Conventional Commits, no emoji, no `Co-Authored-By`.

## Review focus

1. Two browsers advancing the same dossier at once: exactly one runs each stage (Task 5 integration test).
2. A downstream that answers 200 with an unexpected body shape: the stage fails with
   `invalid_response`, never crashes the page (Task 4 contract tests with malformed fixtures).
3. A visitor exhausting the debate budget mid-day: compose shows "budget left: 0" and the API answers
   `budget_exhausted` (429) without calling paper-trail (Task 3 + Task 10).
4. A claim with no lexical overlap with any evidence: selection still returns the top items by role, never
   an empty pool when candidates exist (Task 6).
5. An expired inkthread upload at verify time: the check reports `expired`, not `failed` (Task 9).
