# bastion v2 — rulings made during implementation

Every decision the orchestrator made on the owner's behalf while executing docs/plans/2026-10-20-bastion-v2.md, in the order made, each with what it costs if wrong. Spec: docs/specs/21-bastion-v2.md.

- Ruling A: T1 also deletes the v1 dossier server code that depends on auth (src/features/dossier/server/{pipeline,create}.ts, src/app/api/dossiers/** routes, RunDemoButton/DossierPrompt/VerifyButton, (app)/run, (app)/dossiers) and strips requireRole/session from the remaining (app) pages so they render publicly; T5/T10/T13 rebuild dossiers — spec §3 removes sign-in entirely and the v1 pipeline is superseded — cost if wrong: dossier UI absent between T1 and T13 on the v2 branch only (not deployed).
- Ruling B: T2 creates the new registry and leaves src/lib/registry.ts and src/lib/gateway/services.ts in place; T3 deletes src/lib/gateway/**, src/lib/registry.ts and the proxy route once nothing imports them — keeps every commit compiling — cost if wrong: one extra file lives one task longer.
- Ruling C: T4's inkthread.reading fixture is written from interface I-3 (rollout plan) because the live endpoint ships with WP-7 concurrently; re-record from live in T15 if available — cost if wrong: a schema mismatch caught at T15 live smoke.
- Ruling D: scripts/migrate.mjs runs only when VERCEL_ENV is set (production and preview builds on Vercel); local/CI builds skip it with a log line; CI integration job runs it explicitly — spec requires prod migrations without new secrets; preview shares prod DATABASE_URL so 0002 must be additive (it is) — cost if wrong: a preview build migrates prod early (additive only).
- Ruling E: Task 3's dispatch also fixes two Task 2 minors in src/platform/registry/health.ts + wake route: /version budget = min(3000, remaining) and wake retries the health probe until the 90 s deadline on timeout/502/503 — they sit on the gateway's asleep path and are one-liners — cost if wrong: small T3 scope creep.
- Ruling F: spec §4 "waking" is a client display state while a wake request is in flight (Task 12 WakeGate); Health stays live|asleep|down — the brief fixes the type — cost if wrong: UI shows waking from client timing, not server truth.
- Ruling G: Task 4 dispatch also fixes Task 3 minors 1, 4, 6 — buildRequest refuses '.'/'..' segments (incl. %2e variants) and requires new URL(...) pathname+search to equal the raw path (invalid_input before any side effect); BASTION_KEY_ID trimmed (BOM/whitespace) and validated [A-Za-z0-9._-]+ in one place used by JWKS and /api/public-key; assertCapability requires a budget for cost "llm" — Task 4 adds ~35 string-keyed paths, so the guard belongs at the seam — cost if wrong: small T4 scope creep.
- Ruling H: the gateway does not write audit rows for its own refusals that have no side effect (invalid_input, rate_limited); they are counted in a structured console line instead. Every call that reaches budget reservation is audited — spec §4 audits gateway calls; refusals unbounded by any limit would let one visitor grow the append-only log without bound on Neon free storage — cost if wrong: abuse attempts are visible only in logs, not the audit trail.
- Ruling I: 4xx keeps releasing the budget; Task 4 must confirm per budgeted capability (paper-trail.debate, inkthread.upload, inkprint.leakScan, magpie.scrape*, inkprint.certify*, feathers writes) from the backend code that its 4xx answers happen before any spend, and note any exception as release:false on that capability — cost if wrong: a 4xx-after-spend backend lets a visitor exceed a budget at ≤30/min.
- Ruling J: feathers.createUser is minted admin (not the plan's editor) — feathers_demo gates POST /users to admin, so editor would 403; spec §5 requires the CRUD to work — cost if wrong: one-line revert.
- Ruling K: budgets count units, not calls — certifyBatch reserves items.length units of `certify` (Capability gains `budgetUnits?: (input) => number`, default 1; release returns the same units) — spec's "certificates 200/day" is per certificate and batch certify spends Voyage embedding quota per item — cost if wrong: a batch counts 50 against the day instead of 1.
- Ruling L: Ruling K covers every batch capability — magpie.scrapeBatch reserves sources.length units of `scrape` (each source runs a scrape and may enqueue an LLM heal) — cost if wrong: a 10-source batch counts 10, not 1.
- Ruling M: inkprint.diff is cost "quota" on the `certify` budget, 1 unit per call (it buys a Voyage embedding like certify) — spec bounds paid spend by budgets; a separate budget adds config for no benefit — cost if wrong: diffs share the 200/day with certificates.
- Ruling N: Task 5 ships src/dossier/handlers.ts with not_implemented stubs (Tasks 6-8 replace them); a waiting stage whose not_before is within 10 s is re-advanced by after() sleeping until not_before — keeps the runner self-driving without the page — cost if wrong: one extra sleeping invocation per waiting poll.
- Ruling O: the runner audits a stage outcome only when the stage's status changes (a waiting→waiting poll writes no audit row) — a debate polled every 3 s would otherwise add ~20 rows per dossier to the append-only log — cost if wrong: poll attempts are not individually visible in the audit trail.
- Ruling O (amended): an attempt change also counts as a transition for auditing (a failed retry pending→pending is audited) — attempts are meaningful events; still bounded by max 3 attempts — cost if wrong: at most 2 extra rows per stage.
- Carry to Task 13: after a stage_timeout nothing auto-advances; the dossier page must nudge advance once nextAt (claim + 300 s) passes.
- Ruling P: stage handlers call the gateway with ctx.requestId = the dossier's request_id (never a fresh id) and actor "bastion", no clientIp — the measure stage finds the dossier's queries in every service by that id (spec §6.1) — cost if wrong: an empty perf receipt.
- Ruling Q: wake's 90 s window restarts on every new attempt (store the attempt alongside 'since' in its output and reset when ctx's attempt differs, or expose startedAt on StageContext) — a visitor retry after service_asleep must get a full 90 s — cost if wrong: retries of asleep dossiers fail after one probe.
- Ruling R: accept the one-write crash windows (debate created but debateId not yet stored; certificates issued but not yet saved) as documented residual risk — closing them needs downstream idempotency keys (paper-trail/inkprint changes) for a window of one DB write; budgets still bound the spend — cost if wrong: a rare duplicate debate (≤ the 4/day debate budget) or duplicate certificates.
- Ruling S: evidence_items.content_hash holds the source's own hash (magpie content_hash for web items; sha256 of the candidate text for document passages/tables), inkprint_hash holds inkprint's sha256 — spec §6.3 added inkprint_hash as a separate column; v1 content_hash meant the source hash — cost if wrong: a column rename in docs.
- Ruling T: a retry of the debate stage after a terminal debate `error` starts a new debate (the stage clears debateId on terminal failure, keeping failedDebateIds); the budget still bounds it — "retry from this stage" (spec §6.4) must be able to recover — cost if wrong: a retried failed debate spends one more debate unit.
- Carry to Task 8 (Task 7 follow-ups): dedupe pending seal candidates by key first-wins; count stored null-certificate rows as taken; skip candidates whose text exceeds inkprint's 1,000,000-char limit (logged) instead of failing seal; check transcript.debate_id equals the stored id; debate URL fallback anchor uses #e-<key> like read; Task 8's pure receipt math goes in src/dossier/receipt-math.ts (src/dossier/receipts.ts is Task 7's Postgres adapter).
